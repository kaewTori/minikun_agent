# ตรวจรับคำแนะนำเติมพอร์ต — 8 ต.ค. 2026

คำถามจริง `เรามีงบอยู่ 1000 บาท เอาไปลงทุนอะไรเพิ่มดี` เคยหลุดจากตัวตรวจคำถามเติมพอร์ต
จึงได้คำตอบเริ่มลงทุนทั่วไปที่ไม่อ่าน ledger และเสนอขายของ/เริ่มธุรกิจ
ตัวแก้ไขจัดคำถามนี้เข้า portfolio advice และให้ตัวเลขกับเกณฑ์ที่ตรวจได้เป็นฐานคำตอบ

## ผลที่ตรวจแล้ว

| เคส | ผล |
|---|---|
| พอร์ตอ้างอิง 9 รายการ งบ 5,000 บาท | เสนอเสริมกองทุนตลาดรวมที่มีน้ำหนักน้อย พร้อมยอดทั้ง THB/USD และน้ำหนักตามต้นทุนหลังเติม |
| เปลี่ยนเป็น 3,800 บาท | คำนวณงบใหม่ตามเหตุผลเดิม ไม่อ้างงบเก่า |
| ขอยอดเป็น $ | แปลงแผนล่าสุดด้วย FX ที่มีวันที่และแหล่งข้อมูล ไม่สร้างแผนใหม่ |
| พอร์ตจริง งบ 1,000 → 800 บาท → $ | ใช้ holdings/mandate จริงและอธิบายจากสัดส่วนปัจจุบัน ไม่อ้างพอร์ตอ้างอิงแทน |
| Core ครองพอร์ตอยู่แล้ว/ไม่มีหลักฐานผู้ออกกองทุน/ผู้ใช้ระบุปันผลหรือสินทรัพย์อื่น | ไม่ใช้เกณฑ์เสริม broad core โดยอัตโนมัติ |
| เงินทุกส่วนและ policy | Java คำนวณและตรวจยอดรวม ทั้งการปัดเศษและน้ำหนักหลังเติม ไม่มีการให้โมเดลเขียนตัวเลขเอง |

ชุดตรวจเกี่ยวข้อง 150 รายการผ่าน และตรวจทั้งการตอบปกติกับ streaming
นำขึ้นแอปที่รันอยู่แล้ว: full build ตรวจ 1,390 รายการ ไม่มี failure/error (ข้าม 14 รายการตามเงื่อนไข)
artifact ที่ติดตั้งตรงกับไฟล์ build และ health/db/conversation persistence เป็น UP
การเชื่อมต่อฐานข้อมูลของ live check เป็น read-only พร้อมเทียบ holdings/cost/policy ก่อนและหลัง
ไม่มีคำสั่ง broker หรือการแก้ policy/ledger จากการแนะนำ

## เกณฑ์คำแนะนำ

ข้อมูล fund objective ต้องมาจาก issuer ที่ตรวจได้; เกณฑ์เสริม core ใช้ความสัมพันธ์ของ
กองทุนตลาดรวมกับกองทุนส่วนอื่นในพอร์ต เมื่อไม่ขัดกับ mandate หรือคำถามล่าสุด
เป็นข้อเสนอแบบสมมติฐานระยะยาว ไม่ใช่คำสั่งให้ซื้อ ticker ใดทุกครั้ง
ในกรณีนี้ [หน้า VTI ของ Vanguard](https://advisors.vanguard.com/investments/products/vti/vanguard-morningstar-total-stock-market-etf)
ยืนยันวัตถุประสงค์ด้านตลาดหุ้นสหรัฐโดยรวม

ทุกผลแสดง allocation basis ว่าเป็นต้นทุน ไม่ใช่น้ำหนักตามราคาตลาด
policy ที่ใช้อยู่ไม่ได้ถูกเปลี่ยนให้เข้ากับแผน ถ้าแผนเสริม core เกินเพดานจะแสดงความขัดกัน
และระบุว่าต้องทบทวนหรือปรับแผนก่อนซื้อ ไม่กล่าวว่าแผนผ่าน policy แล้ว
